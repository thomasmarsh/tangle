# Question

Area [[IDX-001-execution-graph]].

Can Tangle replace recursive plan files and hosted issue trackers as an organic memory index for long-lived project work?

Reassesses [[TAS-007-competitive-evaluation]] at context_rev 4.

# Conclusion

The core model is a strong fit for repository-local execution memory and a partial fit for broader project memory. Atomic nodes, authoritative status directories, a routing-only root map, bounded reads, and retained resolved nodes should remain. The graph itself is the distributed index; `index-map.md` is only its bootstrap route.

The approach needs stronger contracts for semantic revisions, edge authority, reachability, recursive roll-up, durable decisions, graph validation, and cold-resumption evaluation before it can be relied on as long-lived organic memory.

# Fit

- Recursive planning is strong because independently actionable subplans become linked nodes rather than nested documents.
- Service independence is strong because Markdown and Git remain authoritative without a hosted tracker, database, daemon, or generated ledger.
- Resumption is strong when a direct node or focus route exists because summaries, next actions, and selective dependency reads bound context.
- Topic and area discovery are incomplete because exact identifiers and metadata queries are stronger than vague cold-start retrieval.
- Long-term integrity is incomplete because edit-count revisions, reciprocal links, orphan nodes, and manual metadata can drift.
