# Question

Which RAG retrieval, context-assembly, indexing, and evaluation directions would most improve Braintree accuracy, usefulness, and token efficiency without weakening Markdown authority or making semantic machinery mandatory?

# Context

The analysis compares the current graph commands, optional semantic and clustering layer, held-out memory evaluation, preserved raw run artifacts, and current GraphRAG and agent-memory research. The requested durable report belongs under `research/`.

# Conclusion

Braintree should remain a governed, Markdown-authoritative execution-memory
graph and adopt RAG techniques at the query layer. The highest-value sequence is
to benchmark the real command surface, compose a bounded query-aware evidence
closure, fuse lexical and optional semantic candidates with typed graph paths,
make retrieval currentness- and section-aware, and complete transparent
incremental indexing. Clustering, generated global summaries, graph propagation,
consolidation, forgetting, and new provenance or temporal fields remain
advisory or evidence-gated.

# Result

`research/rag-perspective-evaluation.md` records the full capability audit,
raw-run verification, evaluation limitations, ranked recommendations, concrete
retrieval packet design, staged evidence program, and directions not recommended
now. The raw artifacts show that the confirmatory seam-reuse case gave
raw-history and Braintree the same memory and, for the v4 models, byte-identical
effective user messages; its differing actions are stochastic reader variance,
not an observed retrieval miss. The current lexical `similar` command returns
the intended `TAS-118` owner at rank one for that case wording.
